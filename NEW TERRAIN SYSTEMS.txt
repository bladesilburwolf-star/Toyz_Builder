The screenshot and the new ZIP make the next step much clearer.

What is now confirmed
Trees are fixed: the GLB trunks are actually reaching the terrain surface. The ground-contact problem is largely solved.
Horizontal logs are now available and wired into Terrain.java. That opens up much better fallen-log, bridge, fort, and forest decoration.
Terrain V2 is already present in the uploaded source:
TerrainGenerator
LandformGenerator
BiomeGenerator
WaterGenerator
TerrainMeshBuilder
LandmarkPlacement
structure-site detection
The water is the obvious remaining weak point. WaterGenerator already generates river paths and carves channels, but Terrain.java still renders the resulting water as repeated DrawCube() slabs. That is exactly the tiled/grid appearance visible in the screenshot.
Direction for the next implementation

I would have Grok move directly to Terrain V3: Water + Depth + Mapgen Presets.

1. Replace the water cubes completely

Remove the current:

DrawCube(water.position, ...)

water rendering.

Instead generate continuous meshes for:

Ocean
Lakes
Rivers
Streams
Frozen water

The river centerlines already exist in WaterGenerator, so build a ribbon/mesh from the actual river path with:

variable width
curved banks
UVs
animated surface
transparent/reflective material
shallow-water coloration
deeper-water coloration
shoreline blending

No water cubes.

2. Use terrain depth instead of only surface height

The new terrain architecture should become conceptually:

Surface Height
      +
Terrain Depth
      |
      +-- soil
      +-- rock
      +-- underground
      +-- caves
      +-- caverns
      +-- tunnels
      +-- underground water

That means caves don't need to be fake sinkholes anymore.

Use a separate deterministic underground/depth field so the surface can remain continuous real geometry.

3. Add the Minetest-style generation presets

Keep the current three modes, but expand the menu concept to:

WORLD TYPE

V2
V3
V4
V5
V6
V7

FLAT
AMPLIFIED

SKY ISLANDS: OFF / ON

STRUCTURES: OFF / ON

They don't have to reproduce Minetest internally. They can be Toyz Builder interpretations of progressively different generation algorithms.

For example:

Preset	Character
V2	Simple classic terrain
V3	More hills/valleys
V4	Stronger erosion/water
V5	Current biome system
V6	Large landforms + structures
V7	Full advanced terrain/depth
Flat	Builder terrain
Amplified	Extreme relief
Sky Islands	Secondary floating terrain system
4. Sky Islands should be real terrain meshes

Not floating cubes.

Generate separate continuous GLB-compatible terrain islands above the main world:

        SKY ISLAND
      /------------\
     / real terrain \
    /________________\

           |

       main world

They can use the same biome/landform system with a different seed offset and then receive trees, rocks, structures, etc.

5. This also makes the temples/forts system much better

The existing LandmarkPlacement can remain the placement layer:

Terrain
   ↓
flatness / slope / water / biome / depth
   ↓
StructureSite
   ↓
Temple / Fort / Village / Bridge
   ↓
authored GLB pieces

And bridges can finally be generated from the actual river mesh, rather than trying to span the old tiled water.

One important source-level change

The current TerrainMeshBuilder is already doing real polygon terrain, which is good. The next major change should be not adding more features to the old Terrain.java water/height system.

Use:

TerrainGenerator
 ├── LandformGenerator
 ├── BiomeGenerator
 ├── WaterGenerator
 ├── DepthGenerator       <-- new
 ├── CaveGenerator        <-- new
 ├── TerrainMeshBuilder
 ├── WaterMeshBuilder     <-- new
 ├── UndergroundMeshBuilder
 ├── SkyIslandGenerator   <-- new
 └── LandmarkPlacement

Then Terrain.java becomes primarily the compatibility/rendering bridge for V8.

That gives us a much cleaner foundation for the next stage instead of continuing to patch the old terrain implementation.

The screenshot confirms the visual target: keep the good continuous GLB terrain and trees, but completely eliminate the Minecraft-looking water grid. The next generation should look like a continuous 3D landscape while retaining the procedural flexibility that makes Minetest's mapgen system useful.
